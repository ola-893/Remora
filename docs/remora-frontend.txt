Remora frontend

UI audit
========
Mobbin finance directory
https://mobbin.com/search/apps/web?content_type=apps&sort=popularity&filter=appCategories.Finance
The search surface keeps result count, category filters and sorting adjacent to the results. Remora keeps name or ID search, activity and status in one bar, with status and USDC rate on each row.

Revolut web transaction flow on Mobbin
https://mobbin.com/apps/revolut-web-538d8553-9169-4343-a90c-66494c577e23/207a7927-16eb-42dc-a110-0584ea786a10/flows#b61c7921-0a5b-49ea-a11c-c51cb9708c59
The home transaction list preserves timestamp, amount and status at a glance. A selected row expands the transaction's supporting detail without losing the list. Remora applies this to fills and wallet actions, with explorer links when the listing includes a NEAR transaction hash.

Coinbase web on Mobbin
https://mobbin.com/apps/coinbase-web-2260d39b-8888-4891-8220-8fe635568d8d/863b441b-4c3b-47fa-b2b3-1a6f60d49c09/screens
The app page and preview were available. Full Coinbase screen access requires Pro and was outside this audit.

Mobbin dashboard audit
https://mobbin.com/blog/what-good-dashboard-design-looks-like
The Origin and Plausible examples pair a focused chart with interpretation or a way to inspect the underlying detail. Remora puts one labeled chart above execution history, shows its unit and source, and lets the reader select a time window or inspect a point. The rate and CLI handoff sit beside the evidence.

Activity detail
===============
Spot trading shows quote output in the recorded paper run, reported P&L if supplied, or counts of published fills. Signed paper or Intents fill metadata stays separate from actual testnet payment transactions.
Staking shows pool actions such as stake, unstake and withdraw through receipt details. Yield needs balance history.
Liquidity ranges show pool actions and receipt details. Time in range, fees and impermanent loss need position snapshots.
Portfolio rebalance shows rebalance activity and receipt details. Weight drift and returns need portfolio snapshots.
Yield reallocation shows lending actions and receipts. Net yield needs balances and valuation.
Reward reinvestment shows compounding actions and receipts. Net reward needs balance changes and costs.
Prediction markets are outside the approved directory because the CLI does not have a supported testnet venue.

Run and register publishers
===========================
From the repository root run npm --prefix vite-project ci, then npm run dev.
Build with npm run build:web. The existing static-host SPA rewrite supports direct agent profile links. The local CLI replay keeps its existing homepage. The browser frontend links to the payment workflow at /workflow.

Add each known publisher to vite-project/public/agents.json as { "id": "ap_…", "origin": "https://publisher.example" }. Use the full ID from agentstream agent show NAME or agentstream publish status and the origin from publish set. The directory only knows registered publishers. Agent identities in private local profiles are not discoverable automatically. Explore also accepts an ID and origin to save a verified offer on this browser.

For a live publisher, enable the intended activity, configure publish set with the HTTPS origin, start publication, and keep agentstream agent run reachable behind that origin. A proxy for an older CLI must expose the public listing and /copy/health with Access-Control-Allow-Origin for the frontend. The updated CLI returns public CORS headers on those endpoints. The paid /copy/actions endpoint remains access-controlled.

CLI 0.9.0 adds optional publish set --public-history to attach recent published action times and native NEAR strategy transaction references to the signed listing. Paper and Intents fill types are identified. The journal and gated action payload stay behind the paid feed. The existing --performance-file attaches publisher-reported P&L. The current schema has no currency or methodology, so the chart labels it in publisher units.

The browser checks the signed offer, ID-to-key binding, activity, origin, execution mode, and current feed health. Agent IDs can be copied for reference. The browser rechecks live terms before copying either CLI command. NEAR settlement can be inspected through a receipt. A publisher signature establishes authorship of a claim, and does not independently validate reported P&L. The recorded Hour Leader is a real paper execution archive with separate testnet payment receipts and shows the original publisher ID.
